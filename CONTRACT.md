# LFG build contract

The single interface every part of LFG agrees on: the CLI, hooks, skills, agents and the dashboard. User-facing docs:
`docs/guide.html` (also `lfg ui` → Help), `docs/sharing.md`, `docs/dashboard.md`.

## Layout

Source checkout: `install.sh`, `plugin/` (the Claude Code plugin with the CLI inside it), `docs/`, `tests/`, `CONTRACT.md`.

After install (`~/.lfg`, mode 700):

```
~/.lfg/
├── plugin/                 # the plugin AND the local marketplace Claude Code loads it from, in place
│   ├── .claude-plugin/{plugin,marketplace}.json   # version lives in plugin.json; defaultEnabled: false
│   ├── bin/lfg             # CLI (python3 -S, stdlib only, 3.9+); on the Bash PATH while the plugin is on
│   ├── lib/lfgcore/        # CLI + dashboard modules
│   ├── skills/<name>/SKILL.md   agents/<role>.md   rules/<rule>.md   hooks/hooks.json   .mcp.json
├── docs/{guide.html,sharing.md,dashboard.md}  CONTRACT.md   # shown in `lfg ui` → Help
├── enabled.json            # where LFG is on: {"everywhere": bool, "repos": {<main checkout>: {...}}}
├── state/ledger.json       # every change LFG made outside ~/.lfg (claudecfg.py), what `lfg uninstall` replays
├── state/{packs.json,gh.json,usage-offsets.json}
├── state/corrections.json # Corrections: {"enabled", "items": [{id, at, kind: said|rejected|interrupted|flagged, said,
│                           # did, why, note, session, cwd, repo, repo_name, status: pending|approved|merged|discarded|
│                           # to second-brain, rule, done_at}]} (mode 600); state/corrections-offsets.json: transcript
│                           # read positions per session
├── state/version.json     # seen: the last version `lfg setup` printed what's new for; news_seen: the last the dashboard's
│                           # What's new walkthrough was shown for (plugin/releases.json, one item per step)
├── state/onboarding.json  # Welcome: chosen features, show-every-page (never in config.json)
├── state/updates.json     # last update check: upstream version, notes, error
├── state/github.json      # whether setup asked to star LFG, and the answer (stars only on yes or a click)
├── repos/<repo-id>/knowledge/*.md  # knowledge the user added (Knowledge → Add knowledge)
├── repos/<repo-id>/insights/reviews.json  # Insights: kinds and counts of findings per check (never code), for "keeps coming up"
├── config.json             # user config, mode 600 (models, lanes, shipcheck, pentest, ports, linear, graphs.docs,
│                           # headroom.port/mode/scope, guard.hardened,
│                           # guard.allow_commit: local commits allowed, not --amend; push/merge stay blocked,
│                           # review.sources: files/folders /lfg:review reads instead of plugin/review/)
├── overrides/{skills,rules}/  defaults/skills/  backups/   # your dashboard edits, pristine copies, backups
├── graphs/<repo-id>/{state.json,docs.json,knowledge.json,.lock,sync.log,knowledge.log}  # bookkeeping only
├── repos/<repo-id>/shipcheck-history.json   # this machine's image sizes; everything else moved into the repo
├── runs/<repo-id>/<run-id>/wt/   # /build's ticket worktrees and /spike prototypes (`lfg run scratch`), never committed
├── omnigraph/{tokens.json (600),src/,dev-graph/,second-brain/}  # local graph clusters + server.log
├── headroom/{state.json,proxy.log}  # proxy upstream + previous ANTHROPIC_BASE_URL (launchd dev.lfg.headroom)
├── ui/static/              # generated viewer pages (e.g. arch-health/<repo-id>.html from /lfg:health)
├── playbooks/<repo-id>/{onboarding,landmines,test-gaps,incidents}.md   # generated from the graphs, never in the repo
├── secintel/cache/  strix/<repo-id>/  feedback/<repo-id>.json  usage.db (600)  audit.log
├── reviews/<owner>__<repo>/<number>.json   # PR review records (`lfg review`), one per PR, a pass per review
├── reviews/passes.json     # findings you passed on for good, in one repo or every repo (below)
├── overrides/review/*.md  # your additions to the review method, read last
```

The repo's own knowledge lives in the repo, committed with the code on the branch it was written on:

```
<checkout>/.lfg/
├── repo-id                 # written once, so every clone and teammate files the repo under one id
├── .gitignore              # keeps out what belongs to one machine (below)
├── docs/{GLOSSARY.md,adr/}  commands.json  shipcheck.json
├── runs/<run-id>/          # 01-brief.md … 07-shipcheck.json, tasks.json, progress.md, run.json
│                           # ignored: CURRENT, patches/, gate-logs/, ready.json, 05-secure.*, 05-pentest.json,
│                           # COMMIT_MSG.md, PR_BODY.md
└── nodes/<Type>/<slug>.md  # shared dev-graph nodes, the master copy (lfgcore/teamknowledge.py)
```

`<repo-id>` = the id in `.lfg/repo-id`; before that file exists, `<repo-dir-name>-<first 8 hex of sha1(git remote
origin url, or the absolute repo path)>`. `<run-id>` = `YYYYMMDD-HHMM-<slug>`. The **current run** is in the
checkout's `.lfg/runs/CURRENT` (per checkout, never committed).

dev-graph keeps each repo on its own branch, `repo/<repo-id>`; the MCP server is pinned to it
(`OMNIGRAPH_DEFAULT_BRANCH`). `lfg knowledge sync` copies nodes agents added or changed there into `.lfg/nodes/`, then
rebuilds the branch from the files; the files win when both sides changed. Shared: Decision, Learning, Invariant,
Principle, Gap, Assumption, ExternalBlocker, Component, Capability, SpecFile, Incident and free-text Issues (`iss-…`).
Never shared: Linear-mirrored Issues, PR, Commit, Release, Deployment, Actor (emails), Comment. second-brain is personal
and never synced.

Tests: `python3 -m unittest discover -s tests` (stdlib, temp `LFG_HOME` and `HOME`, a fake `claude`) + `lfg doctor --selftest`. Lint: `uvx ruff check plugin/lib plugin/bin/lfg tests`, `shellcheck install.sh bootstrap.sh`, `claude plugin validate plugin`.

## Footprint: what LFG may change outside ~/.lfg

Only through `claudecfg.py` (backup, compare-and-swap, ledger entry), only after the user agreed (`lfg setup` plan, `lfg enable`, `lfg add`, the dashboard with the edit key), and never anything the guard calls user-only (agents can't run `lfg setup|enable|disable|uninstall|add|remove|changes undo|headroom setup|off`):

| Change | When | Undo |
|---|---|---|
| `~/.local/bin/lfg` symlink | setup | removed |
| `claude plugin marketplace add ~/.lfg/plugin` (Claude Code records it in `extraKnownMarketplaces`) | setup | `marketplace remove`, empty key dropped |
| `claude plugin install/enable lfg@lfg --scope local` → `enabledPlugins` in `<repo>/.claude/settings.local.json` | `lfg enable` | `uninstall --scope local`, empty key/file/folder LFG created dropped |
| LFG's graph folders in `<repo>/.git/info/exclude` | `lfg enable` | exactly those lines removed |
| deny rules in `<repo>/.claude/settings.local.json` | hardened mode | exactly those rules removed |
| `env.ANTHROPIC_BASE_URL` → Headroom, per repo (`scope: repos`) or in `~/.claude/settings.json` (`everywhere`) | Headroom pack | restored if still LFG's value |
| launchd agents `dev.lfg.headroom`, `dev.lfg.omnigraph.<name>` | Headroom / Knowledge packs | booted out, plist removed |
| user-scope MCP `linear` (only if you have none) | Linear pack | `claude mcp remove` |
| `claude plugin install lfg@lfg --scope user` | `lfg enable --everywhere` | `uninstall --scope user` |
| launchd agent `dev.lfg.dictate` (runs `plugin/lib/lfgcore/dictate_helper.py` in `~/.lfg/dictate/venv`) | Dictate pack | booted out, plist removed, `~/.lfg/dictate` deleted |

Revert restores a value only while it still equals what LFG wrote. Homebrew/uv installs are listed (`state/packs.json`), never removed. Older versions' machine-wide changes (global deny rules, the `~/.claude/CLAUDE.md` block, user-scope MCP servers, global Headroom routing, the plugin on everywhere) are detected exactly by `setup.legacy_items()` and offered for clean-up by `lfg setup --migrate`, the dashboard and `lfg uninstall`.

## CLI (`lfg <command>`). Every command: exit 0 = ok, 1 = failed check, 2 = usage/env error. `--json` where noted.

| Command | Does |
|---|---|
| `lfg setup [--packs a,b] [--here] [--everywhere] [--migrate] [--dry-run] [--yes] [--json]` | Install or update: read-only scan → plan → apply after a yes; a failed step rolls back this run's changes. `install.sh` runs it |
| `lfg enable [path] [--hardened] [--everywhere]` / `lfg disable [path] [--everywhere]` | LFG on/off for one repo (or machine-wide); `disable` undoes exactly what `enable` changed, keeps graphs and runs |
| `lfg packs [list\|add\|remove] [<name>] [--yes] [--no-scripts]`, `lfg add <pack>`, `lfg remove <pack>` | Optional packs: security, shipcheck, pentest, knowledge, linear, headroom. Core is always on |
| `lfg changes [list\|undo <id>] [--json]` | The change ledger; `undo` reverts one entry if it is still LFG's |
| `lfg uninstall [--dry-run] [--keep-data] [--yes]` | Replays the ledger backwards, cleans up older installs and LFG launchd agents, removes `~/.lfg`; lists tools and repo graph folders left behind |
| `lfg mcp <code-review-graph\|dev-graph\|second-brain\|headroom>` | The plugin's MCP servers (`plugin/.mcp.json`): the real server when its pack is ready, else a stub with no tools that says how to add it |
| `lfg dictate [status\|restart] [--json]` | LFG Dictate (pack `dictate`, off until `lfg add dictate`): on-device speech-to-text anywhere on the Mac. Hold the shortcut (`dictate.shortcut`, default Option+Space) to talk, double-tap for hands-free; text is put where the cursor is (`dictate.insert`: paste\|type) and also left on the clipboard. Runs cactus-needle's Whistle model offline (telemetry off, Hugging Face offline, explicit weights path). `dictate.cleanup` (on by default) sends text only to `claude -p`. No audio or transcript is kept; `~/.lfg/dictate/state.json` holds permissions, last error and today's count |
| `lfg version` | Version |
| `lfg doctor [--selftest]` | Tools of the packs that are on, Claude Code + marketplace, where LFG is on, Docker, Omnigraph, a Headroom proxy that is down, gh auth, leftovers from older installs, the ledger; `--selftest` proves every forbidden action is blocked |
| `lfg init [--rebuild]` | First-time setup for the current repo (graphs + repo dirs). Normally automatic |
| `lfg graphs ensure [--background] [--allow-stale] [--rebuild] [--json] [--quiet]` | **Graph preflight.** Builds on first use, syncs if code changed (incl. uncommitted). Exit 1 if graphs can't be made fresh |
| `lfg graphs status [--json]` | `fresh` / `syncing` / `stale` / `missing` |
| `lfg graphs docs [--quiet]` | Regenerates graphify's wiki + call-flow view, code-review-graph's wiki and the playbooks (no LLM, no network). Runs automatically in the background after a sync changes the graphs (`graphs.docs` in config.json, default on). Writes `graphs/<repo-id>/docs.json` |
| `lfg playbooks` | Writes only the playbooks: onboarding tour, landmines (code notes, untested security code, cycles, churn × untested), test gaps, incident runbooks (from dev-graph) |
| `lfg run new <slug>` | Creates a run folder, sets CURRENT, prints its path. In a linked worktree: prints the run whose `run.json` lists the worktree instead of starting another; with none, creates the run in the main checkout's `.lfg/runs/` listing the worktree (the main checkout's CURRENT is untouched) |
| `lfg run path [<file>]` | Prints the current run folder (or a file inside it): in a linked worktree, the run in the main checkout that lists it, else the checkout's CURRENT. Exit 1 if no current run |
| `lfg run merge <from-run> [<into-run>]` | Moves a duplicate run's files into another (default: the current run) and removes it. A file both have keeps into-run's and saves the other as `<name>.from-<from-run>.<ext>`; `run.json` gains its worktrees, skipped steps and `merged_from` |
| `lfg run review-stamp` / `lfg run review-status` | `review-stamp` (run by /lfg:expert after writing `06-review.json`) records the checks it was written against and the commit it read, and prints the line to open the review with when they weren't green. `review-status` (run by /lfg:ship) exits 1 when the review was written while checks were red and commits landed since; a review on red checks with the code unchanged stands |
| `lfg run list` | Recent runs for this repo |
| `lfg run use <run-id>` | Makes a run in `.lfg/runs/` current, e.g. a teammate's on this branch. In a linked worktree: moves the worktree onto that run's `worktrees` list |
| `lfg run scratch` | Prints this machine's folder for the current run (`~/.lfg/runs/<repo-id>/<run-id>`), for /build worktrees and /spike prototypes |
| `lfg knowledge sync` / `status` | Brings `.lfg/nodes/` and the repo's dev-graph branch level (SessionStart and Stop run it in the background with the Knowledge pack on); `status` shows the folder, branch, file count and leftovers in `~/.lfg` |
| `lfg knowledge migrate [--dry-run] [--take-main-nodes]` | Moves runs, glossary, ADRs and commands kept in `~/.lfg` under any id this repo had into `.lfg/`, merging a run found under two ids; originals go to `~/.lfg/backups/`. `--take-main-nodes` also copies the shared nodes on dev-graph `main` (where older versions kept every repo's) into this repo's files |
| `lfg run set [lane=…] [stage=…] [issue=<ID or title>] [--force]` | Records lane, stage and issue in the current run's `run.json` (what the dashboard shows). A stage moves the linked dev-graph Issue (plan → todo, build/fix/check/secure → in_progress, expert/ship → needs_review, done → done). Refuses to lower the lane without `--force` |
| `lfg run doing <step>` / `lfg run done <step>` | Marks a step started or finished in the current run's `run.json` (`steps: {step: doing\|done}`). The run page shows a started step as in progress, not done, even once its file exists (a drafted brief before approval). Without a mark, a step is in progress while `stage` is on it and it has no output yet; for brief, design, tasks and build, also while its output is only a draft. Checks, security, review and ship check are over when their verdict is in; a failing one shows as a problem |
| `lfg run skip <step> "<why>"` / `lfg run unskip <step>` | Records a step left out on purpose in the current run's `run.json` (`skipped: {step: why}`; steps: brief, design, tasks, build, qa, gate, secure, review, ship, packet). The run page shows it as skipped with the reason and moves "next" past it. Commits on the run's worktree branch show Built as done outside LFG; a step before one that ran shows as not recorded |
| `lfg issue sync <ID\|title> [--title] [--type] [--status] [--priority 0-4] [--description] [--criteria] \| show <ID> \| sync-tasks \| sync-brief [--json]` | `sync-tasks`: one Issue per task in the current run's tasks.json (description + steps, verification as acceptance criteria, done once `passes`), called by /plan and /build. `sync-brief`: the brief's Problem and Acceptance criteria onto the run's Issue, called after /grill. `sync`: creates or updates the Issue in dev-graph as the writer role (`ACME-4225` → slug `acme-4225`, `legacyRef` kept; an idea → `iss-<kebab>-<4 hex>`, or the existing issue with that title). The Issues page lists these; skills call it at intake |
| `lfg rule <name>` | Prints a hidden rule module (`tdd-rules`, `slice-rules`, `domain-docs`, `module-design`, `bug-loop`, `agent-writing`, `git-guard`, `graph-first`, `remember`, `worktrees`), or the user's own version from `~/.lfg/overrides/rules/<name>.md` (changed or added in the dashboard). SessionStart lists rules the user added |
| `lfg repo docs [--branch [NAME]]` | Prints the repo's docs dir (glossary, ADRs, project-wide docs the user asked for): `<checkout>/.lfg/docs`. `--branch` prints `<checkout>/.lfg/docs/branches/<branch>/` for docs about one branch's work (checked-out branch by default; the real name is kept in `.branch`) |
| `lfg repo knowledge` | Prints the per-repo folder of knowledge the user pasted in the dashboard (Markdown notes, decisions, lessons, rules), never inside the repo |
| `lfg repo id` | Prints `<repo-id>` (the same in every worktree and clone of a repo) |
| `lfg repo root` / `lfg repo graph` | Prints the main checkout / its `graphify-out/graph.json` (also from a linked worktree) |
| `lfg worktree new <branch> [--from <ref>]` / `list` / `remove <name\|branch>` | Checks a branch out in `<parent>/<repo>.worktrees/<branch-slug>` (an existing branch, or a new one from `--from`, default HEAD) without touching the user's checkout, and records it in the current run's `run.json` `worktrees`. `remove` only takes worktrees it made, refuses any with uncommitted or untracked changes, never forces and keeps the branch. Agents run it on their own (rule module `lfg rule worktrees`); SessionStart removes LFG worktrees that are clean and unused for 24 h |
| `lfg lane [--json]` | Suggests a lane from the diff + code-review-graph impact (`express`/`standard`/`full`/`hotfix`) with reasons |
| `lfg gate [--json] [--fix] [--affected] [--only lint,types,test,build,secrets,suppressions]` | The green gate: lint, types, tests, build, gitleaks, new-suppression check. Results from exit codes; a check that failed only because a program it starts isn't installed here (`spawn qpdf ENOENT`, `command not found`) is N/A, "can't run here", with an install hint: not red, and not green either. `--fix` runs the detected formatter/fixer first; `--affected` narrows tests to graph-impacted files where the runner supports it. Writes `ready.json` |
| `lfg ci-local [--list] [--affected] [--json]` | Replays lint/type/test/build `run:` steps from `.github/workflows/*.yml` locally (only steps the guard allows; steps using `${{ }}` are skipped); `actionlint` + `zizmor` on workflows. Progress on stderr: each step as it starts and ends, and each minute a step is still running. `--affected`: only workflows a push or PR with this branch's changed files would start (their `paths`/`paths-ignore`; a workflow with no filter always counts) |
| `lfg secure [diff\|all\|<pkg@ver>\|<url>\|<image>] [--json] [--offline]` | Local scanners + metadata-only online intel. Writes `05-secure.json` when a run is active. In `diff` mode a finding in a file the branch doesn't change (against the default branch, plus uncommitted files) is `on_main: true`, "already on main", and doesn't count toward the verdict or the exit code. Exit 1 on a blocking finding |
| `lfg pentest [--target <local url>] [--mode quick\|standard\|deep] [--model <ollama model>] [--preflight] [--json]` | Strix with a local Ollama model only, on a scrubbed copy of the repo. Refuses non-local targets, non-loopback Ollama, a missing sandbox image, or no egress firewall. Writes `05-pentest.json` |
| `lfg shipcheck [--cleanup] [--json]` | Ship check (gate 8): Docker build → scan → run on internal network → smoke test → delete → verify cleanup, plus shipping checklist. Writes `07-shipcheck.json` |
| `lfg watch` | Read-only: follows the CI run of the current branch via `gh` |
| `lfg hotspots [--days 180] [--json]`, `lfg why <file>[:start-end] [--json]` | Read-only git: files that keep needing fixes (with reasons and trend; generated files left out), and the commits that shaped a file or lines with their PR, issue and Linear links. The dashboard's Insights page shows both |
| `lfg ui [--port 7777] [--no-open] [--unlock]` | Dashboard on 127.0.0.1: read-only except Settings and Skills, which need the local edit key (handed to the browser in the URL fragment, never printed). Pages, rules and API: [docs/dashboard.md](docs/dashboard.md) |
| `lfg claudemd show\|remove-legacy` | Shows `~/.claude/CLAUDE.md`, or removes the marked block an older LFG appended, only if it is byte-identical to one LFG shipped. LFG no longer writes this file: the same guidance is session context in LFG repos (`hooks.CONTEXT`) |
| `lfg sonar setup \| status \| scan [--base REF] \| issues \| cloud [--base SHA] \| login \| stop \| remove [--data] [--json]` | Optional SonarQube pack (`lfg add sonarqube`; needs Docker and Node). `setup` pulls SonarQube Community 26.10 (pinned by digest), runs it as container `lfg-sonarqube` on 127.0.0.1:9000 with labelled volumes, replaces admin/admin with a generated password and makes a scanner token (`~/.lfg/sonarqube/credentials.json`, 0600; only `login` prints it), and installs SonarSource's npm scanner `@sonar/scan@5.0.2` into `~/.lfg/sonarqube/scanner` (`--ignore-scripts`). `scan` copies the git-tracked and new, non-ignored files (never secret-looking ones, never over 20 MB) to a scratch folder, analyses it natively (token in the environment, never argv), honours `.sonarcloud.properties` / `sonar-project.properties`, and writes `repos/<rid>/sonar.json` (gate, conditions, measures, every open issue and hotspot, `mine` = on a line this branch changed against `--base`, default origin's default branch). Exit 1 when a bug, vulnerability, hotspot or major-or-worse issue is on a changed line. `cloud` reads SonarCloud's own verdict for a commit from its GitHub check run (read-only). `remove` only touches resources labelled `lfg=sonarqube`; `--data` also drops the volumes and the credentials. /lfg:check runs `scan` when the server is up |
| `lfg omnigraph setup [--no-launchd] \| status \| restart <name> \| serve <name> \| mcp <name> [--json]` | dev-graph + second-brain (Knowledge pack): creates the graphs from the pinned Omnigraph cookbooks (no seed data), generates per-machine tokens (never printed), runs each server on 127.0.0.1 under a launchd agent `dev.lfg.omnigraph.<name>` (in the ledger). `serve` clears a cluster lock left by a server that died (only when the pid in `__cluster/lock.json` is gone, via `omnigraph cluster force-unlock`) and, if another server already answers on the port, waits and takes over when it stops; `restart` reloads an agent launchd gave up on; `lfg doctor` flags a brain that answers but isn't kept running by its agent. The plugin's `.mcp.json` provides MCP `<name>` → `lfg mcp <name>` → `lfg omnigraph mcp <name>`, only in LFG repos. Agents search with LFG's keyword queries in `plugin/omnigraph/{dev-graph,second-brain}.gq` (`find_*`, `save_note`; bm25, local, no API key); the cookbook's embedding `search_*` queries need an OpenAI/OpenRouter/Gemini key and are never used |
| `lfg headroom setup [--scope repos\|everywhere] [--upstream URL] \| status \| restart \| off \| serve [--json]` | Optional (Headroom pack, off by default): runs `headroom proxy` on 127.0.0.1:`headroom.port` under launchd `dev.lfg.headroom` (`headroom.mode`: `cache`, the default, or `token`, which rewrites earlier turns and so re-sends the whole conversation; no rate limit, no response cache, telemetry off, `--lossless`), forwarding to the previous `ANTHROPIC_BASE_URL` or api.anthropic.com. Routes Claude Code there only once the proxy answers: per LFG repo (`.claude/settings.local.json`, default) or everywhere (`~/.claude/settings.json`), all through the ledger. Refused on Bedrock/Vertex/Foundry. `off` undoes exactly that routing and unloads the agent. The SessionStart hook restarts a dead proxy Setup never adopts the Claude desktop app's own `ANTHROPIC_BASE_URL` (its gateway takes the app's sign-in, not the claude.ai login terminal sessions send); without a setting it forwards to api.anthropic.com. |
| `lfg feedback add <finding-id> accept\|reject [--note ...]` | Records your verdict on a review finding |
| `lfg review context\|save\|show\|list\|mark\|post\|threads\|ask\|replies\|remember\|pass\|passes [<pr>] [ids…]` | Reviews of other people's PRs (`/lfg:review`). `<pr>` is a number (repo from this checkout), `owner/repo#12` or a PR URL. `context`: what the review reads (sources, the PR's AGENTS.md files, whether it is a re-review, `description` (the PR body), `ticket` (the Linear id its branch, title or description names; `LFG_REVIEW_TICKET`, set by `lfg review run --ticket` for one PR, wins), and `settled`: what you already decided, below). `remember <pr> <id> --to dev-graph\|second-brain [--note TEXT]`: saves what a finding's discussion settled, to the place you name every time (no default): a decision in the repo's own dev-graph branch (needs a local checkout of the repo) or a note in your second-brain. The text is the finding, its place, your note or its decision (dropped: not a problem here; kept: a real problem) and the last turns of the discussion; refused for a finding that is undecided with no `--note`, or with no discussion and no `--note`, or already saved to that place. The title starts `Review: `. Unattended review runs may not call it. Dashboard: the chat about a finding, "Save for this repo" / "Save for me". `pass <pr> <id> --scope pr\|repo\|all [--note TEXT]`: passes on a finding for good (drops it, then says how far "don't flag this again" reaches): `pr` is what dropping always did (never raised again on this PR unless worse), `repo` every PR in this repo, `all` every repo; the last two are kept in `reviews/passes.json` and refused for a comment already on GitHub. `passes [<pr>] [--json]` lists them (those that apply to the PR's repo, else all); `passes --remove <id>` takes one off (the finding stays dropped on its PR). ## Hooks

`plugin/hooks/hooks.json` calls `"${CLAUDE_PLUGIN_ROOT}/bin/lfg" hook <event>`, with matchers limited to the tools LFG inspects (`Bash|Read|Edit|Write|MultiEdit|NotebookEdit|NotebookRead|WebFetch|mcp__.*`; SessionStart on `startup|resume`). Every hook first checks `C.is_enabled(cwd)` (a filesystem walk to the main checkout + `enabled.json`; no subprocess, no heavy imports) and exits 0 where LFG is off. SessionStart prints `hooks.CONTEXT` (what used to be the `CLAUDE.md` block) plus `hooks.TAG_RULE`: use an LFG skill whenever one fits even if the user didn't type the command, and start every reply with `**LFG:** /lfg:<skill>`, `**LFG:** tools only (<which>)` or `**LFG:** not used - <reason>`. UserPromptSubmit adds the one-line `hooks.TAG_REMINDER` to every prompt. Both follow `replies.lfg_tag` (default true; Settings → General). Stop reads only the transcript bytes appended since the last Stop, and, when `replies.lfg_tag` is on (off by default), records each reply's LFG line (`skill`, `tools`, `not-used` with its reason, or `missing`) in `usage.db` table `replies`, shown on the Usage page.
Outside systems (`plugin/lib/lfgcore/outside.py`, [docs/guard-read-write.md](docs/guard-read-write.md)): gcloud, gsutil, bq, aws, az, kubectl, supabase, psql, mysql, clickhouse-client and the Supabase and ClickHouse MCP tools are judged by what the command does. A read is always allowed on every environment (impersonation flags change nothing); a write, or anything not recognized as a read, is blocked (rule 15, rule 11 for SQL); a command that prints a secret value is blocked by rule 5. One write anywhere in a compound command (`&&`, `;`, pipes, `xargs`, `find -exec`, `$(...)`, `bash -c`, loops, heredocs) blocks the whole command. A SQL client pointed at localhost may write. Otherwise SQL is judged by its statements: a CTE hiding an UPDATE, or several statements with one write, is a write.
PreToolUse blocks with exit code 2 + a reason on stderr: `Blocked by LFG rule <N>: <why>. A human must do this in their own terminal. (plus the Preferences → Safety rules row to lift).
Git and GitHub actions (`guard.ACTIONS`, one Preferences row each, `act_*`, Block / Ask / Allow; only once Preferences are switched on, before that rules 1 and 2 block them all): Allow: commit, push to a branch that isn't main/master/qa/prod/production, open a PR, edit your own open PR's title or description, comment on a PR or issue, reply to or resolve a review thread, catch up with the remote (`--ff-only`); Allow when no uncommitted work is lost, else Ask (`guard.SPARES_WORK`, judged with `git status` in the folder the command runs in, following `cd` and `-C`; a folder LFG can't see counts as losing work): stash, restore a file, switch branch; Ask: push to main, force-push, merge a PR, rewrite history (amend, rebase, reset to another commit), delete or rename branches. Reads are always allowed. A git or gh write with no row falls to rule 1 (Other git writes) or 2 (Other GitHub writes). Block exits 2: `Blocked by LFG: "<row>" is set to Block (<why>). Change it in lfg ui → Preferences → Git and GitHub actions → "<row>" ...`. Ask prints `hookSpecificOutput.permissionDecision: "ask"` naming the row, so Claude Code (or Studio's Allow / Deny) asks first; `guard.check()` (the gate, ci-local) treats Ask as blocked. The rows say whether a command may run; Commits, Push, Opening PRs and Merging PRs still say when Claude does it, checked by the prefs hook, whose blocks name their row too. The old `edit_pr` and `git_ff_sync` switches migrate to `act_edit_pr` and `act_ff_sync` (on: Allow, off: Block).

## Secrets in tool output

PostToolUse cannot rewrite output, so LFG **detects + warns + audits**: when output matches a secret pattern the hook returns `{"decision":"block","reason":...}` telling the model not to repeat it, and writes an audit entry (pattern name only, never the value).

## MCP servers

Declared by the plugin in `plugin/.mcp.json`, so they exist only where the plugin is on: `code-review-graph`, `dev-graph`, `second-brain`, `headroom`, each started as `lfg mcp <name>`.
